# Model Zagrożeń (STRIDE) – SecureBank

| ID | Element DFD | Zagrożenie | STRIDE | Ryzyko | Planowane środki zaradcze (Mitygacja) | Standard MASVS |
| :---: | :--- | :--- | :---: | :---: | :--- | :--- |
| **TH-01** | Magazyn lokalny | Zapis tokenów JWT w nieszyfrowanym AsyncStorage | I | Wysokie | Zastąpienie AsyncStorage sprzętowym magazynem `expo-secure-store` / `react-native-keychain` (Android Keystore, iOS Keychain). Wyłączenie backupów systemowych. | MASVS-STORAGE-1 |
| **TH-02** | Baza danych (PostgreSQL) | Brak lub błędna polityka RLS (podatność BOLA/IDOR) | E, I | Wysokie | Wymuszenie polityk Row Level Security (`auth.uid() = user_id`) na tabelach `profiles`, `accounts`, `transactions`. Weryfikacja tożsamości wyłącznie z podpisanego tokena JWT. | MASVS-AUTH-1<br>MASVS-AUTH-2 |
| **TH-03** | Inne aplikacje -> Aplikacja mobilna | Podsłuchanie lub wymuszenie przelewu przez Deep Link Hijacking | S, T | Wysokie | Traktowanie parametrów linku jako niezaufanych. Brak automatycznych przelewów – link wypełnia jedynie formularz; bezwzględny wymóg autoryzacji biometrycznej/PIN przed wysłaniem. | MASVS-PLATFORM-1 |
| **TH-04** | Aplikacja mobilna -> Backend API | Przejęcie transmisji sieciowej (Atak Man-in-the-Middle) | I, T | Wysokie | Wymuszenie TLS 1.3, weryfikacja certyfikatów, planowane wdrożenie SSL Pinningu dla endpointów Supabase API. | MASVS-NETWORK-1<br>MASVS-NETWORK-2 |
| **TH-05** | Backend API (Supabase Auth) | Atak Brute-force / Credential Stuffing na formularz logowania | S, D | Średnie | Rate limiting po stronie Supabase Auth (blokada IP/konta po seriach błędnych prób), wymóg bezpiecznych haseł (min. 8 znaków). | MASVS-AUTH-3 |
| **TH-06** | Baza danych (Audit Logs) | Wyparcie się wykonania transakcji przez klienta | R | Średnie | Niezmienna tabela `audit_logs` w PostgreSQL z uprawnieniami INSERT-ONLY (rejestracja czasu, IP, `auth.uid()` i szczegółów operacji). | MASVS-AUTH-4 |
| **TH-07** | Aplikacja mobilna (WebView) | Wstrzyknięcie złośliwego kodu JS (XSS) i ucieczka z WebView | T, I | Średnie | Wyłączenie dostępu do plików lokalnych (`allowFileAccess=false`), brak eksponowania wrażliwych interfejsów mostka, filtrowanie domen zewnętrznych. | MASVS-PLATFORM-2 |
| **TH-08** | Aplikacja mobilna (Kod klienta) | Pozostawienie sekretów produkcyjnych w kodzie aplikacji | I, E | Wysokie | Wykluczenie klucza `service_role` z kodu źródłowego i konfiguracji klienta. Użycie wyłącznie publicznego klucza anonimowego (`anon-key`) ograniczonego przez RLS. | MASVS-CODE-1<br>MASVS-CODE-2 |
| **TH-09** | Aplikacja mobilna (Moduł biometrii) | Fałszywe zatwierdzenie biometrii przez modyfikację pamięci (Frida) | S, T | Średnie | Powiązanie pomyślnej autoryzacji biometrycznej z odblokowaniem klucza kryptograficznego w sprzętowej enklawie (Keystore/Keychain), a nie pojedynczą flagą logiczną. | MASVS-CRYPTO-1 |
| **TH-10** | Użytkownik -> Aplikacja mobilna | Podglądanie stanu konta (Shoulder Surfing / Zrzuty ekranu) | I | Niskie | Wdrożenie flagi `FLAG_SECURE` na Androidzie (blokada screenshotów i podglądu w przełączniku zadań), zamazywanie widoku przy przejściu w tło oraz maskowanie salda. | MASVS-STORAGE-2 |
| **TH-11** | Backend API -> Usługa zewnętrzna | Odmowa usługi lub sfałszowane kursy walut z zewnętrznego API | D, T | Niskie | Krótkotrwały lokalny cache ostatnich poprawnych kursów, timeouty zapytań (3s) oraz sanityzacja wartości liczbowych. | MASVS-NETWORK-1 |
| **TH-12** | Aplikacja mobilna (Pamięć RAM) | Pozostawanie wrażliwych danych w pamięci po wylogowaniu | I | Średnie | Funkcja `logout()` bezwzględnie czyści stan pamięci aplikacji, usuwa tokeny sesji z Keystore i unieważnia sesję w Supabase GoTrue. | MASVS-STORAGE-1<br>MASVS-AUTH-1 |
